## 作者上手

**选择编辑器目录和魔兽根目录 → 导入视频 → 生成视频包 → 打开编辑器 → 使用对应触发器动作 → 进入游戏测试。**

1. 在“快速创建视频包”选择两个目录。魔兽目录检查 `war3.exe`；编辑器目录检查 `WorldEdit.exe` 或 `KKWE.exe`。没有找到时会提示，可确认“仍然继续”。
2. 导入 MP4 视频，可多选或拖入。视频自带音轨会一起播放，导入不转码。
3. 填写 MIX 名称，点击右下方的“生成视频包”。工具自动把播放器和视频封装到所选魔兽根目录，完成后显示实际路径。
4. “为编辑器安装触发器动作”默认勾选。不需要安装时可以取消，编辑器目录也可以留空。
5. 安装完成后打开或重启编辑器，在“视频播放”分类使用动作，填写包内视频文件名，例如 `开场.mp4`，再进入游戏测试。

## 玩家使用

玩家只需将作者发来的 MIX 包放到实际使用的魔兽根目录，不用运行管理器。未安装视频包的玩家跳过视频表现。

## 可选：启用本地文件读取

注：从未使用过任何外置包的作者/玩家可能需要安装注册表。工具内点击“安装注册表”先显示确认提示，继续后由 Windows 打开导入窗口，确认导入后重启魔兽。注册表已内嵌到工具，单独复制 EXE 也可打开安装提示。按地图作者要求，作者和玩家都可双击随包的 `启用魔兽本地文件读取.reg`，确认 Windows 导入提示后重启魔兽；已经开启的无需重复导入。作者分发时，可将该文件与 MIX 一起提供，并注明按需导入。

注册表设置为当前 Windows 用户的 `HKEY_CURRENT_USER\Software\Blizzard Entertainment\Warcraft III` 下 `Allow Local Files = 1`，用于允许游戏读取本地文件。它不负责安装播放器或编辑器触发器动作。

## 更新与维护

根目录已有视频包时，会询问“保留旧视频并更新”或“仅使用本次视频”。原包保留为备份并停用，根目录只留一个启用的视频包。同名导入视频替换旧内容，其他插件不会被覆盖。

“管理已有视频包”提供打开、导出、增删视频和保存。“管理已有视频包”页内可单独安装、卸载触发器动作。KKWE 注册 config.user，YDWE 注册 config，保留其他配置。已经使用视频动作的地图在卸载前需删除或替换相关动作。

若 MIX 创建成功而触发器安装失败，保留生成的 MIX 并提供单独重试安装，不必重新导入视频。确认目录继续不代表未知编辑器布局一定可安装；不支持的布局会明确提示。

更新播放器后需要重启魔兽。运行中使用的文件被占用时，先退出相应程序再更新；工具不自动关闭游戏或编辑器。

## 功能与范围

播放给所有玩家/指定玩家，停止指定玩家/所有玩家，音量 0–100%、速率 0.25–4，自动读取时长。地图动作在同步流程调用；视频仅做本地表现，不回写同步状态，不把本地播放完成用于奖励或剧情结算。视频画面覆盖游戏窗口，音量不受游戏内声音设置影响，已经移除全局 ESC 自动跳过。

建议 H.264/YUV420P + AAC MP4，解码依赖 Windows 媒体栈。支持具有 bin、jass、share/mpq/config 的编辑器配置布局。

历史实机范围是 Windows、War3 1.27a、同机双方安装插件的窗口化 LAN。快速创建与目录确认、更新替换、自动安装、失败保留包以及文件占用保护经定向测试；完成弹窗通过真实 WinForms 流程检查。YDWE 未启动真实编辑器；独占全屏、KK 平台、新版/Reforged、跨机器和混装未验证。

## 源码与构建

源码：[GitHub](https://github.com/Bzsga/war3-video-mix)。已发布版本以仓库更新记录为准。

版本入口 src/AppVersion.cs。Windows .NET Framework 4.x 与 Zig 下依次运行 build.ps1、build-autostart.ps1 -Zig <zig.exe>、build-manager.ps1。构建管理器会内嵌播放器、原生启动器和触发器定义，不需另拷 GUI 文件。

公开验证摘要见 [VALIDATION.md](VALIDATION.md)。原始私人路径、地图和素材不发布；历史实机/夹具范围不可混用。

生成前会检查视频列表和来源文件、所选目录。没有视频、视频为空/缺失/不完整、魔兽目录未选或不存在，以及勾选安装动作但编辑器目录未选或不存在时，不生成视频包。取消安装动作后编辑器目录可留空；此前确认继续使用无程序标记目录的选择仍有效。

## 再次打开与保存

工具会记住所选的魔兽目录、编辑器目录和安装选项。再次打开时，根目录只有一个有效视频包就自动打开并切到“管理已有视频包”；没有包则保留快速创建，多个包则提示手动选择。首次也会尝试工具所在魔兽目录或系统登记的安装目录。显式指定打开某个 MIX 时，以该文件为准。

管理页右下方为“保存视频包”，保存成功后底部显示实际路径。触发器维护区显示当前编辑器目录；“另存为”仍可另选位置。上次设置失效或损坏时会提示重新选择，不自动生成文件。个人目录设置存放在当前Windows用户的本地应用数据中，不随软件包分发。

## 退出稳定性修复（1.1.9）

原生模块安装文件钩子后保留到游戏进程结束，防止Miles释放插件后游戏仍调用已卸载的路由代码。播放器对未变化窗口减少位置更新，并使用不激活、不调整所有者层级、不发送同步位置改变通知的异步窗口标志。

旧版在显式插件卸载后文件访问的原生夹具中复现访问异常；新版连续三次正常，真实WPF播放中关闭目标后播放器退出。双窗口独立停止与音频回归通过。公开摘要见 [VALIDATION.md](VALIDATION.md)。此轮没有复现用户地图的退出卡死，不能保证所有地图或平台的退出问题均已解决。

现有 MIX 需通过新版管理器保存或刷新后重启魔兽，单独替换管理器不会更新已经分发的包。

## 响应与保存优化（1.1.10）

首次播放的视频在后台解包，停止或关闭游戏会取消解包并清理临时文件；已缓存视频继续直接使用。无变化请求按时间戳和大小跳过重复读取，另保留每秒内容复查，避免遗漏保留时间戳的改写。部分写入不会标记为已处理。

管理页保存、快速创建和命令行共享目录写入锁。来源包已被其他工具更新时拒绝用旧列表覆盖，需重新打开；其他 MIX 插件不能被覆盖。在魔兽根目录以新名称另存时，提示备份并停用原包，避免两个视频包同时加载。保存仍保留原包备份。

退出监测仅请求最小等待权限；受保护客户端不允许打开进程句柄时使用 PID/窗口兼容路径，不因权限不足停止启动。诊断日志写入失败也不会中断播放。

本机 1 GiB 包解包中退出的原生夹具对照：播放器从约 2.39 秒降至 0.38 秒，不再退出后继续启动解码，未残留解包临时文件。普通播放退出约 0.4–0.5 秒，未测到明显加速；这是播放器夹具时间，不能当作用户地图的魔兽退出时间。无变化期间两秒读取操作由 36–38 次降至 4–6 次。并发、旧列表冲突、取消、备份及实际管理页保存回归通过。公开摘要见 [VALIDATION.md](VALIDATION.md)。

补充实机：两份实际War3菜单客户端通过MIX播放视频/音轨、指定停止保留另一端音频、播放中正常关闭；有视频包关闭约 [1.66, 1.45] 秒，临时停用视频包对照约 [1.42, 1.34] 秒（均含所属启动器退出轮询）。这不是用户地图退出时间。此次LAN没有成功入局，不记作新版地图内多人同步通过。完整范围见 [VALIDATION.md](VALIDATION.md)。
